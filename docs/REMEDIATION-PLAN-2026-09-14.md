依赖方向：CLI 装配 Adapter 和核心 Module；核心分析依赖项目契约与小 Interface。核心分析不导入 EasyAIoT 数据表或 HTTP 字段。平台更换不修改事件状态机，模型更换不修改告警处置流程。

### 4.1 分析 Module

Interface：逐窗口接收观测，产出标准事件；控制窗口生命周期、策略推进和正常结束。Implementation：模型调用、策略、证据关联。模型后处理保留在模型 Adapter，不把厂商张量传进业务层。

本轮 `stream()` 与离线 `run()` 共用同一条策略路径，避免离线与实时各写一套规则。

### 4.2 实时源 Module

- Interface 输出帧/窗口、采集时间、源周期、健康状态，支持显式停止。
- 文件 EOF 为正常完成；RTSP read 失败进入可恢复故障，不直接作为业务正常结束。
- 明确连接超时、读取超时、指数退避、最大退避与停止信号。
- 帧队列必须有上限，过载按明确策略丢旧帧并记录丢帧数。
- 重连产生新源周期，旧轨迹不跨周期复用；旧事件结束原因记录为中断/超时。
- FPS 缺失、为零或非有限值要给出清晰处理，不依赖摄像头总能报告可靠 FPS。

验收：连接拒绝、密码错误、断网、恢复、空读、帧冻结和主动停止均有确定状态；停止后无句柄或后台线程遗留。

### 4.3 交付 Module

- 分离本地 enqueue 和网络 drain；本地事务成功即可让分析继续。
- 每个交付工作循环持有自己的 SQLite 连接，不能跨线程共享现有默认连接。
- 增加 attempts、next_attempt_at、last_error、delivered_at，迁移前备份数据库。
- 对 429/可重试 5xx/网络错误做退避；字段错误进入可检查的失败队列；鉴权失败明确告警。
- 按 event_id 保持 revision 的顺序，避免 END 先于 START 落地。
- 接收端按 idempotencyKey 建唯一约束或等效事务去重；重试不能创建重复业务事件。
- 采用至少一次交付语义，显式测试“服务端已落库、客户端未收到响应”的重试场景。
- 设置积压上限和磁盘水位；禁止空间不足时静默抛弃告警。

验收：平台不可用时推理仍推进、事件在本地可查询；重启后可补传；重复重放不增加业务事件数；成功依据是平台确认接受而非单纯 TCP/HTTP 通。

### 4.4 证据 Module

- 证据对象包含 event_id、源周期、类型、哈希、大小、状态和访问 URI。
- 区分已生成、待上传、可访问、生成失败和已过期。
- 上游支持对象存储时复用其授权上传接口；否则采用明确的受控文件服务，不直接暴露本地目录。
- 采用唯一文件名、临时文件写入后原子完成；避免重复运行覆盖旧事件证据。
- 明确前后缓存窗口和实际片段长度；采样窗口不能默认称为完整事发录像。
- 上传失败不丢事件，事件页面显示证据状态；后续补齐通过可追踪更新完成。
- 清理保护未交付事件、处置中的事件和受保留策略保护的证据。

验收：从平台所在机器实际打开截图和视频；断网补传成功；满盘时记录证据失败但事件仍入本地 outbox。

## 9. 日志、指标与故障排查入口

建议结构化日志字段：runId、cameraId、sourceEpoch、eventId、revision、modelVersion、configVersion、阶段、耗时和错误类别。凭据不进入日志。

最低指标：最后成功读帧时间、窗口推理延迟 P50/P95、事件生成到入库耗时、入库到平台确认耗时、outbox 待发数/最老年龄、重试数、证据失败数、磁盘水位、进程 RSS、队列长度和主动丢帧数。

排查顺序：视频是否推进 → 模型是否输出 → 策略是否生成事件 → 本地是否入库 → 平台是否确认 → 平台是否可见 → 证据是否可打开。每一步保留独立证据，避免将“没在页面看到”直接归因给模型。

## 10. 回退与变更管理

- 本轮不提交、不推送、不切换分支、不改已有数据库、不重启服务。
- 源码回退按文件差异选择性恢复，不能使用 `git reset --hard` 清除用户未提交内容。
- 流式新增接口保留旧离线接口；后续迁移逐个入口进行，不一次改全部 CLI。
- 视频恢复使用审计清单里的 recovery_path；恢复前验证目标不存在，恢复后验证 SHA-256。
- 平台版本更新前保存上游 SHA、配置和数据库备份；涉及不可逆迁移必须先验证恢复流程。
- 发布前固定模型和策略组合；回退同时恢复匹配版本，避免只退代码、模型仍为新版。
- 不为“整理项目”重新初始化 Git、覆盖原始数据或丢弃训练产物。
