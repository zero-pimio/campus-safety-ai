# 人员打架事件规格 v1

## 定位

人员打架是视频时序行为，不是单帧目标类别。第一版接收视频分类模型对一个时间窗口输出的 `fighting` 分数，再由事件状态机形成正式事件。官方 PP-Human 同样把打架识别归为视频分类。

## 生命周期

- 开始：`fighting` 分数连续高于 `start_score`，覆盖时间达到 `confirm_seconds`，发出 `START`。
- 保持：分数位于开始与结束阈值之间时保持已打开事件，但不能用来确认新事件。
- 结束：分数连续低于 `end_score`，覆盖时间达到 `clear_seconds`，发出 `END`。
- 冷却：事件结束后 `cooldown_seconds` 内不重新开始同一摄像头事件。
- 去重：同一事件的每个 revision 使用稳定 `idempotencyKey`。
- 时间：使用带时区的真实时间戳和视频窗口，不按帧数估算持续时间。

## 主体

如果上游能把行为窗口与人员轨迹可靠关联，事件携带参与者 `subjectTrackKeys`；纯全画面视频分类不能可靠定位参与者时允许为空，不能编造人员身份。

## 困难负样本

- 拥抱、拉扯和同学嬉闹；
- 篮球、足球、武术或体育课；
- 多人快速跑动、围观和拥挤；
- 摄像头抖动、强遮挡和快速切镜；
- 单人挥手、摔倒或搬运物品。

## 当前边界

- 已实现：行为观测契约、阈值迟滞、持续确认、START/END、冷却、幂等和固定回放。
- 未实现：真实 PP-Human/PaddleVideo adapter、人员轨迹关联、视频窗口采样、证据截图/短录像、模型训练和校园数据评测。
- 不允许：使用“两个人靠近”“框重叠”“运动速度快”单独判定打架；自动触发高风险处置前必须保留人工复核。
