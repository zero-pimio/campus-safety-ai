# 车辆违停规则诊断：低分观测与驻留清零

日期：2026-09-23。结论基于 UT 和新增 PNNLParkingLot2 的检测缓存重放、当前真实 ByteTrack 适配器和当前 `ParkingAnalysis`；诊断侧没有执行新检测模型、训练、修改业务代码或调整演示门限。当前旧视频不能作为“停车后离开”的正例交付。用户最新要求是先换新的视觉识别演示，本轮规则保持不变。

检查前的三个假设依次为：低置信度观测占主导；短低分会破坏同轨迹驻留；检测框运动超过固定起点位移门限。实测支持前两项，第三项在当前缓存中未发生。

即使跨越整段视频、暂不考虑任何间隔超时或运动重置，所有“相邻两个处理帧都具有合格同轨迹”的区间合计也只有 **4.8 秒**。这是下文有效观测时间方案在此缓存上的宽松上界，仍远低于 30 秒。因此，允许短暂低分暂停计时也不应使这个 UT 样本成为可靠停车正例；降低门限或补造时间不能补齐素材证据。

原片是 UT-Interaction 的人员互动视频，车辆被画面边缘裁切，人工配置区域且没有车辆违停真值。它可以展示真实检测流程，但“0 告警”不是负例正确，也不是停车规则已经验收。应改用完整可见车辆、停车超过原阈值并自然驶离的真实素材，补充正常通行/短停对照。

## 发现二：短暂低分清零是明确的保守策略，但会让周期性质量抖动永远无法完成驻留

当前候选要求连续合格观测。只要一帧同轨迹分数低于 0.4，`observed` 不包含该轨迹；候选被清空并移出 `_states`。`max_observation_gap_seconds=2` 不是“候选允许两秒漏检”：它主要处理状态过期；候选仍会在第一次低分/缺失输入时立即重置。已有测试明确要求这个行为，不能把它称为与现行规格不一致的代码错误。

最小单变量反例使用 5 Hz、固定不动且始终在区内的车框、真实 ByteTrack、原 30 秒门限；所有运行都只有一个稳定轨迹 ID：

| 输入 | START |
| --- | --- |
| 始终置信度 0.95 | 30.0 秒 |
| 只把 29.8 秒那一帧改为 0.39，之后恢复 0.95 | 60.0 秒 |
| 29.8、59.8、89.8、119.8 秒各出现一帧 0.39 | 到 120 秒仍无 START；每段最长候选 29.6 秒 |

准确表述是：**孤立一帧低分会延迟触发；在达到驻留阈值前周期性出现一帧低分，可反复清零而长期不触发。** 不能写成“一次低分后永远不会触发”。0.39 仍高于当前 ByteTrack 高分门限 0.25，所以反例没有借助丢轨或换 ID；只触发了事件规则的 0.4 门限。

已开启事件与候选也不同：短低分通常让已有事件继续 OPEN，且不能用缺失确认离开。这是避免未知观测被当成“车辆已经离场”的保护，应保留。

依据：[立即清零路径](../../../src/campus_safety_ai/core/parking_analysis.py#L181)、[长间隔路径](../../../src/campus_safety_ai/core/parking_analysis.py#L123)、[已开启事件处理](../../../src/campus_safety_ai/core/parking_analysis.py#L155)、[现有短缺失语义测试](../../../tests/test_parking_analysis.py#L115)。

## 发现三：新 PNNL 中视觉检测稳定，短低分与重建 anchor 共同阻断 30 秒驻留

对 `runtime/parking-improvement-20260923/baseline/detections.jsonl` 复用相同诊断器，加载其 `run.json` 指定的原停车策略和 `configs/scenes/pnnl-parking-demo.toml`，未改门限。中央白车由其区域内轨迹 `pnnl-parking-demo:1:bytetrack:2` 对应：

| 指标 | 实测值 |
| --- | ---: |
| 总处理帧 / 观测跨度 | 250 / 49.8 秒（原视频 50 秒） |
| 中央车同一轨迹返回 | 250 / 250；无换 ID |
| 区域内合格帧 | 244 / 250（97.6%） |
| 该轨迹分数 min / median / max | 0.2456 / 0.8267 / 0.9118 |
| 相邻合格区间合计 | 48.2 秒 |
| 最长严格候选 | 0.0–23.0 秒，共 23.0 秒 |
| 低分清零 / 固定 anchor 位移清零 | 2 次 / 1 次 |
| START / pre_eof_END / EOF_END | 0 / 0 / 0 |

六个低分帧分成两组：23.2/23.4/23.6 秒，分数约 0.284/0.344/0.300；24.2/24.4/24.6 秒，分数约 0.246/0.308/0.313。23.2 秒第一次清零，23.8 秒重新开始，24.2 秒再次清零。24.8 秒恢复后重新建立 anchor `(0.514928,0.633526)`，28.0 秒当前点 `(0.511525,0.613743)` 与该 anchor 距离 **0.020073527**，略超过原 0.02 门限，于是再重置。最后一段 28.0–49.8 秒只有 21.8 秒，无法触发 30 秒门限。

关键区分：相对 **0 秒最初 anchor** `(0.514438,0.617197)`，全片所有合格观测的最大位移只有 **0.016336216**，始终小于 0.02。这次“移动重置”与低分后重新选取的检测框 anchor 有关，不能据此认定白车真实移动，也不能优先靠扩大 `movement_threshold` 修饰结果。如果以后评估短缺失容错，应同时检查是否保留原可信 anchor；不能只把累计秒数保住却把 anchor 换成暂时偏移的框。

与 UT 不同，这段具备稳定、完整车辆的视觉展示价值，且确实暴露了现有严格驻留策略对短质量波动的敏感性；但本轮仅交付新视觉演示，未实施上述规则改动。PNNL 同样没有违停标注或真实停车许可语义，人工框定区域不能把其中车辆定义为现实违法行为；片段中的自然离场也未由本次事件计数证明。

数据：PNNL 完整统计（本地产物：`runtime/diagnostics/parking-rule-pnnl-summary.json`）、中央车逐段诊断（本地产物：`runtime/diagnostics/parking-rule-pnnl-central-track.json`）。

## 建议：有限容错，但只累计有证据的驻留时间

这是待实现的新策略语义，不是本轮已修复或已在视频验证的能力。保留当前严格模式以兼容旧回放，新增显式策略版本；不要直接把低分帧当成静止、简单用首尾时间差代替证据时间，或为旧演示降低 30 秒门限。

候选内部增加 `observed_stationary_seconds`、`previous_sample_valid`、`last_valid_at`、短未知间隔起点和累计未知预算；固定 `anchor` 不随微小漂移滚动。规则可按以下方式定义：

1. 同一视频源周期、同一可靠轨迹、在区内且相对固定 anchor 未移动，只有**相邻两次处理输入均合格**，且时间间隔不超过允许的观测配对上限，才将二者的媒体时间差加入有效驻留。首次合格样本只建立 anchor，累计为 0。
2. 低分、缺失或身份不确定时进入 UNKNOWN，冻结累计值；既不增加驻留，也不确认离开。短间隔后可信地恢复同一轨迹、位置仍接近同一 anchor 时可恢复候选，但不计入从旧合格帧跨越未知区间到新合格帧的时间。
3. 超过短间隔宽限、累计未知预算、候选最大跨度，或轨迹到期、换 ID、源周期切换、明确出区/移动时，丢弃候选重新计时。不能凭 ByteTrack 仍保留同一 ID 就跨越长时间未观测区间。已开启事件沿用原有超时收口、冷却和 END 幂等机制。
4. 所有时间使用输入 `captured_at`，不按墙钟推理耗时、帧数或解码暂停计时。状态只保留活动候选及既定短期冷却，超时清理，不能无限累积历史片段。

5 Hz 回放可先讨论 `max_valid_pair_gap_seconds=0.3`、`unknown_grace_seconds=0.6`、候选累计未知预算 2 秒与候选最大跨度 32 秒。这些只是针对采样率的**设计例值**，未调参、未执行或验证，不能直接作为线上默认值；实际配置要同时约束采样间隔和遮挡风险。

例如，29.8 秒的一帧低分应排除 `[29.6,29.8]` 和 `[29.8,30.0]` 两个区间。其余观测可信且稳定时，到 **30.4 秒** 才累计足够 30 秒；不是 30.0 秒即触发，也不是把未知当成驻留。若未知持续或反复耗尽预算，则重置而非继续攒时间。

## 回归与交付验收

实施时应在真实 `ParkingAnalysis.advance` 调用边界固定下列输入，并保持原有反例作为严格模式预期；本轮没有修改或新增核心测试：

- 稳定静止 30 秒：一个 START；随后明确移动/出区达到退出门限：同一 eventId、revision 连续的自然 END。短停和移动经过无 START；EOF 关闭单独统计，不能替代自然离场。
- 一帧低分后恢复：严格模式仍在 60.0 秒触发；新有效观测时间模式只在达到 30 秒可计区间后触发（上述例为 30.4 秒），未知期间不得产生 START。
- 长 gap、重复/倒序输入、源周期切换、换 ID、轨迹到期：不能延续旧候选；未知区间不确认离开；已有告警/冷却不能被低分抹掉。
- 缓慢持续运动：虽然相邻帧位移很小，相对固定 anchor 的累计位移超过门限仍重置；不以移动 anchor 拼出“静止”。
- 周期性低分：短间隔可以冻结，但未知总预算/最大候选跨度会限制拼接；连续低分/长期遮挡永不靠时间流逝触发，候选内存有界。
- 对新完整车辆视频保留原始 source/model/config SHA、固定检测缓存、可视化计时和重放一致性；区分真实正例、短停负例和未知覆盖。验收应包括 START 和自然 END、触发延迟、误报/漏报与跟踪连续性，不只要求视频画出框。

本轮结论止于诊断与方案：未改变 `core`、`tests`、`settings` 或场景 CLI，未宣称违停问题已经解决。原始视频和检测缓存保持不变。
