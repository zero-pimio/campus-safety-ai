# 恢复因队列容量被拒绝的事件

`deliver-events` 只重试已经入库的记录。`recover-events` 用于核对并恢复同一运行目录内 `unsubmitted-events.jsonl` 的被拒绝记录，**只进入本地现有 Outbox，不连接平台、不发送网络消息**。恢复完成也不能写成告警已送达。

## 先核对，再显式入库

先停止该运行的全部视频生产程序和投递程序，保留运行目录及其中的数据库、审计、被拒绝记录。下面的默认命令只生成核对报告：

```bash
.venv/bin/python -m campus_safety_ai.apps.recover_events \
  --runtime-dir runtime/fall-camera-01
```

报告包含两个日志的 SHA-256、字节数和记录数、唯一事件记录数、已存在数、预计新增数、当前积压、容量限制和 `capacity_allowed`。`blocked` 表示当前容量无法容纳整个新增批次；不会选择性跳过部分事件。容量默认与持续跌倒入口一致：10,000 条和 64 MiB 待发送有效载荷。已有相同幂等键与相同有效载荷的记录不占新增容量，即使之后调低容量，也可完成重复核对。

确认报告后，以相同参数显式加 `--apply`：

```bash
.venv/bin/python -m campus_safety_ai.apps.recover_events \
  --runtime-dir runtime/fall-camera-01 \
  --apply
```

工具取得现有 Outbox 投递独占锁，重新核对输入，并在一个 SQLite 写事务内同时验证重复记录内容、事件版本顺序和容量，然后原子入库整个新增批次。如果 START 已在库中、只有 END 被拒绝，仅恢复原来的 END，保留原事件 ID、版本、时间和幂等键，不重新制造 START。容量不足、内容冲突或版本乱序会明确失败，不部分恢复。

若需要先腾出待发送容量，须在另一步确认平台可用并使用 `deliver-events` 交付原积压；该步骤可能真实发送告警，恢复工具不会代替执行。恢复后的记录仍需由正常投递程序继续发送。

## 验证与路径边界

- 只接受显式运行目录下固定名称的 `events.jsonl`、`unsubmitted-events.jsonl`、`outbox.sqlite3` 及其 WAL。拒绝目录或文件符号链接、额外硬链接及路径中的 `..`；不寻找其他运行或项目数据。
- 每条拒绝记录必须是完整的 `EventRecord`，并与 `events.jsonl` 中对应生成记录的有效载荷一致。审计中的 `sourceEpoch`、`reason` 是附加审计字段，不改变事件有效载荷。
- 拒绝日志中的重复幂等键、生成审计中的重复幂等键和 Outbox 中的已有幂等键，都必须对应相同内容。任何冲突整批拒绝。版本必须从原始 START 连续延续，不能在 END 后追加，也不能把拒绝记录倒序导入。
- 日志、数据库和 WAL 单文件读取上限默认 **64 MiB**，可通过 `--max-file-bytes` 显式调整。文件变化、截断、半条 JSON、超限或旧数据库缺少当前 schema 时明确拒绝。旧数据库迁移应独立处理，不能在恢复时悄悄改造来源。
- 默认核对会把有界主数据库与 WAL 复制到临时目录读取，包含已提交但尚未 checkpoint 的记录；避免 SQLite 只读连接仍在原目录创建 WAL/SHM。临时副本不交付事件，结束后清理。
- 应停止全部生产程序；投递锁只排斥发送者，不能代替停止独立生产连接。入库事务还会再次检查同键内容和事件版本，防止核对后另一个生产连接插入冲突记录。

## 原文件、回执与中断恢复

`--apply` 只追加 `recovery-receipts.jsonl`，记录此次唯一 attempt、源/审计 SHA-256、幂等键序列 SHA-256、容量和数量。入库前持久化 `planned` 回执，提交后记录 `enqueued` 和实际新增条数。原 `unsubmitted-events.jsonl` **不删除、不截断、不自动归档**，`events.jsonl` 同样保留。

如果在数据库提交之后、成功回执写完之前中断，原日志和 `planned` 回执仍在。再次执行核对和 `--apply` 会按原幂等键识别已存在记录，实际新增数为 0；不会重复插入，不会自动重复发送。不能仅凭 `planned` 回执判断是否提交，必须重新核对数据库。回执写入失败会向调用方报错，即使该批已经入库，也不会假装整个恢复步骤完成。

由于原被拒绝日志仍非空，证据维护工具会继续保护该运行的证据。应在人工核对入库及后续交付状态、保留日志与回执校验信息之后，再单独决定如何可恢复归档。此工具不宣称自动完成整套告警恢复和证据清理闭环。

本次只在临时测试目录验证：默认核对无原目录写入、含 WAL 的完整快照、END 单独恢复、重复导入、内容冲突、版本缺失/乱序、竞争生产者、满队列原子拒绝、投递锁占用、文件上限/链接拒绝以及提交后回执故障重试。未对现有真实运行记录执行恢复，未发送真实平台告警。
