# 车辆违停事件规格 v1

事件类型为 `illegal_parking`。规则输入是同一摄像头、同一视频源周期中的车辆轨迹；输出使用现有 `EventRecord` 的 `START`、`END`、revision 和幂等键。该模块判断图像中的持续驻留，尚不能替代实际道路违停执法判断。

- 目标类别：默认 `car`、`truck`、`bus`、`motorcycle`，置信度至少为 `minimum_confidence`。
- 禁停区：使用目标框底部中心点和归一化多边形，区域包含边界。事件配置来自 `configs/events/parking-v1.toml`；场景的 `[parking_zone]` 提供区域标识和多边形。
- 开始：车辆进入区域时建立固定 anchor；后续观测与该 anchor 的归一化欧氏距离始终不超过 `movement_threshold`，持续达到 `stationary_seconds` 后发出 `START`。`startedAt` 是这一段连续驻留的起点，`observedAt` 是确认达到阈值的时刻。
- 缓慢行驶：每次位移与固定 anchor 比较，超出阈值即以当前位置重新计时。不会把不断累积的小步位移当作长时间静止。但实际位移一直小于阈值的车辆仍可能触发，应结合机位和误报样本调整参数。
- 结束：已开始事件的车辆持续离开区域或远离原 anchor 达到 `exit_seconds` 后发出 `END`。短暂移动后回到原位置会取消结束计时。
- 漏检与缺帧：空观测、低置信度和未获得当前帧轨迹都会中断开始前的驻留计时，也会中断离区/移动的确认计时。已打开事件允许短暂遮挡；轨迹被跟踪器判定过期，或与最后有效观测的间隔超过 `max_observation_gap_seconds`，立即结束并清理该轨迹。长间隔前后的时间不会拼接成连续驻留。
- 冷却：正常结束后，同一轨迹在 `cooldown_seconds` 内不开始新事件，也不累计下一次驻留；冷却到期后重新建立 anchor。低置信度或短漏检不会清除尚未到期的冷却状态；状态在冷却到期、跟踪器明确报轨迹过期或源周期结束后清理。丢轨后出现的新轨迹不能继承旧轨迹的身份或冷却时间。
- 顺序与周期：重复/倒序序号、相同/倒序采集时间不推进状态。每个摄像头仅保留当前源周期水位；旧周期观测不会恢复已结束事件。切换源周期、轨迹过期及 `finalize(camera_id, source_epoch, ended_at)` 均收口已打开事件，END 保留原摄像头和轨迹标识。结束时间不会早于该轨迹最后一次有效观测。
- 内存：轨迹过期和 EOF 清理轨迹状态；源周期切换清理旧周期状态。每个已见摄像头保留一个水位用于拒绝迟到数据，不按历史周期无限累积。默认跟踪器按摄像头独立；调用方注入的跟踪器应支持其实际流复用方式。

默认参数为驻留 30 秒、距离阈值 0.02、移动/离区确认 2 秒、冷却 30 秒、最大观测间隔 2 秒。阈值使用带时区的采集时间，不能由处理帧数代替。

验收至少包含固定停车、低速穿越、短暂停留、离区与移动恢复、遮挡和低置信度、丢轨、断流、重复数据、冷却后重新停车。当前测试覆盖规则行为，不构成真实摄像头、车辆检测/跟踪精度或平台联调验收。尚未识别真实世界速度、拥堵排队、授权停车、号牌或移动机位。
