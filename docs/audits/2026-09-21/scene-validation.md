# 2026-09-21 闯入与违停本地视频验证

本轮沿用已有 YOLO26n 权重，补齐人员/车辆的检测、跟踪、区域事件和本地可靠投递；没有新训练或替换打架权重。原基线 SHA256 仍为 `da569fb56931ecf1fdbabff11b6b3fa902661b6c2d9c62b65b6f8d88032041af`。

## 实现与修复

- 新增 `scene_video` 入口：显式场景 TOML、逐帧检测、闯入/违停策略、独立 SQLite Outbox、事件截图、可视化录像和运行报告。源视频、模型和配置保留 SHA256，输出目录拒绝覆盖。
- `SceneVideoPipeline` 复用现有检测、跟踪和事件契约，闯入/停车共用同一视频执行流程。`offline_replay --event parking` 可直接重放固定检测。
- 闯入：漏检或低置信度不再被计入连续进入/离开时间；超时、源周期切换和 EOF 收口；拒绝时间回退；区域边界明确包含；历史状态按源周期清理。
- 违停：仅车辆在人工配置区域内，相对固定驻留起点的累计位移不超过阈值且持续 30 秒才开始。逐帧小幅移动仍会因累计位移超过阈值重新计时。已覆盖移动结束、离区、冷却、漏检、丢轨与源周期结束。
- 修复独立审查发现的冷却漏洞：低置信度间隔不能提前清除同轨迹的停车冷却。
- YOLO 检测入口保留置信度至少 0.1 的候选供跟踪器恢复，事件判断仍使用策略中的 0.4 门限。跟踪前过滤非目标类别，避免人员和车辆交叉关联。
- 解码/推理失败、渲染失败和中断均有事件收口路径。证据写入失败记录错误，不抑制事件；投递本身失效则保留失败状态和可持久化的记录，不宣称已送达。

停车未触发的关键观测：车辆大多被画面边缘裁切；339 个处理帧中仅 52 帧有车辆置信度达到 0.4。在演示区域内，任意符合门限车辆的最长连续检测跨度仅 1.0 秒（不是同一轨迹驻留指标），不足以支持 30 秒持续停车判断。没有为演示降低门限、补造检测或复制片段延长停车时间。

这说明停车规则和入口可以运行，但还没有通过可靠的真实停车正例验收。下一步需要完整可见车辆、正常通行/短停/长停对照和区域事件标注；不能把这段 0 告警视频当作停车准确率证据。

## 当前适用范围

新入口面向本地恒定帧率录像，时间按原始帧号除以 FPS 计算。每路视频独立分析器；ByteTrack 缓冲仍按处理次数计算，事件连续性额外受媒体时间间隔限制。停车在图像坐标中判断驻留，没有世界速度、拥堵、停车许可或车牌语义。

本轮未做实际 RTSP 重连/长稳、远端平台收包、校园精度、板卡部署或其他动作训练；没有改变这些验收状态。部署前需要接入真实授权机位并完成事件级误报、漏报、延迟和长稳验证。
