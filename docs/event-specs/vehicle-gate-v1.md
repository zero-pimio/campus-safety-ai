# 车辆闯道闸事件规格 v1

状态：设计稿，尚未实现或通过现场验收。本文约定车辆通行、授权核对和演示验收；共享术语、输入记录与关联规则见 [门禁与道闸总体设计](../design/access-control-v1.md)。本次只交付设计，不代表已经接入控制器、运行新策略或生成演示视频。

## 1. 目标与边界

识别固定机位下车辆穿越指定道闸通道的过程，结合只读的 `GateSignal` 判断该次通行是否具有有效授权，用 `PassageAssessment` 保存依据与不确定性。未经授权的完整通行才可形成车辆闯道闸事件；探入、压线、倒车、闸杆抬起或车距很近不能单独证明闯闸。

规则不控制道闸开闭，不推断驾驶员身份，不把视觉轨迹当成真实车辆身份，也不把视频越线当成授权证据。撞杆、故意破坏及危险驾驶不属于本版可确认结论。

目标类别保留模型原始标签，并通过版本化映射归入现场的车辆规则。首批可评估 `car`、`truck`、`bus`、`motorcycle`；`bicycle` 和 `person` 必须有独立的通道规则，不能因共享车道就消耗机动车额度。类别抖动不能创建新通行。骑手与车辆重复框、推车、拖挂车和连体车辆的计数规则须先由标注规范确定；无法可靠区分时输出 `uncertain`。

## 2. 输入与最小场景标定

| 配置或输入 | 要求 |
| --- | --- |
| 摄像头与通道 | 固定 `cameraId`、`gateId`、`laneId`；一条通行必须绑定一个明确通道 |
| 方向 | 几何上标定驶入和驶出；政策另行定义各方向为要求授权、自由通行或禁止通行；正向授权不能覆盖反向通行 |
| 区域 | 外侧等待区、闸口通行区、内侧完成区、有效车道多边形、遮挡/忽略区 |
| 有向线 | 每个方向的进入线和完成线；线的两侧、有效线段及跨越顺序必须可视化核对 |
| 越线判定 | 参考点、滞回距离、稳定观测时长、最大观测间隔；参数由该机位回放确定 |
| 类别与计数 | 允许类别、未知类别处理、拖挂及骑手组合计数规则；版本化保存 |
| 授权协议 | 授权有效期、方向、额度、对象绑定方式、预约/消费规则、撤销语义及消费点 |
| 外部信号 | `GateSignal` 的来源标识、发生时间、接收时间、序列/去重键、数据新鲜度和完整性水位 |
| 时间质量 | 视频与控制器时钟偏差上限、允许乱序/迟到窗口；超过容差即降级 |
| 运行状态 | 普通、人工放行、维护、消防/应急等模式及每种模式的可信来源和通行规则 |
| 证据 | 预录/后录范围、通行审计保存位置、证据缺失原因及配置/模型版本 |

车辆参考点可以从经标定的框底部中心开始，但两条线必须对应现场通行方向和透视关系。跨越完成线表示满足已标定的完整路径证据，不自动表示车尾已清空闸杆下方；整车清空须由另行验证的占用算法或独立传感器确认。需要实际距离或速度时再增加地面标定，不从像素距离直接推导米或公里/小时。

场景启用前必须将上述几何、方向和参考点叠加到真实录像检查。摄像头移动、裁切、分辨率或镜头变化使标定失效时，停止确定性判定并重新标定。

## 3. 通行状态机

每次通行使用一个 `passageId`，不直接以跟踪器 ID 代替。状态由连续、可信的观测推进；同一源周期内必须满足几何方向、车道、有效跨越线段和观测间隔约束。几何方向描述实际运动，不表示政策允许该方向；禁止驶入的方向仍须能够观测完整穿越。

| 状态 | 进入条件 | 后续处理 |
| --- | --- | --- |
| `approaching` 接近 | 从方向对应的起始区域取得稳定车辆观测 | 建立候选；尚未发生完整通行 |
| `crossing` 进入闸口/穿越中 | 在滞回带外取得进入线两侧的连续可信观测，随后沿该几何方向向完成侧运动 | 按现场协议预约/消费额度；可显示进入闸口和穿越中两个子阶段，不额外增加共享状态值 |
| `completed`、direction=inbound 完成驶入 | 由外侧经进入线到完成线，在内侧取得规定的稳定观测 | 完成一次驶入，形成或更新 `PassageAssessment` |
| `completed`、direction=outbound 完成驶出 | 由内侧按反向标定的线序到外侧取得稳定观测 | 完成一次驶出，按驶出规则核对授权 |
| `aborted` 退回 | 尚未完成通行，连续观测到目标返回原起始侧并达到稳定条件 | 不记完整闯闸；只释放尚未消费的预约 |
| `unknown` 结果不完整 | 在闸口中途首次出现，或尚未完整穿越时观测缺口超限、丢轨、标定失效、源周期结束 | 记录原因，结果为 `uncertain`；不补造穿越路径 |

在线上抖动不反复触发跨越；仅压线、车头探入再退回不等同于完整通行。完成后短暂倒退不能清空原 passage 的消费记录或重复上报原事件；随后若满足另一方向的完整路径和两侧稳定观测，则是第二次通行，使用新 `passageId` 并按反向政策核对。第一程完成侧的稳定观测可以作为第二程起点，不额外要求等待固定冷却时间。

同一车辆多次进出通道是否为新通行，由完整状态循环决定，不能仅靠固定秒数冷却。车道级冷却不能抑制随后另一辆车的独立通行。

## 4. 授权核对与额度

`PassageAssessment.outcome` 只使用共享约定的四种值：

| outcome | 本场景含义 |
| --- | --- |
| `authorized` | 已按现场协议无歧义关联或分配适用该通道、方向、类别、时间及政策的有效授权，且额度足够；不存在未解决的冲突 |
| `unauthorized` | 完整通行已确认，授权时间窗口已经收敛；完整可信授权流及政策证明没有适用授权/可用额度，且关联与时间质量满足条件；拒绝日志只能作为经关联的辅助依据 |
| `uncertain` | 授权仍可能迟到、日志不完整、时钟超差、绑定不唯一、信号冲突或通行证据不完整 |
| `not_required` | 现场配置明确该方向/类别/模式不要求授权，并且当前模式来源可信；缺失授权日志不能产生此值 |

普通入场默认核对授权；自由驶出是否为 `not_required` 必须由现场规则明确。人工抬杆和维护常开不自动表示免授权，更不自动授予无限额度。

禁止方向不等于自由方向。普通授权不能覆盖可信政策明确禁止的方向；若现场允许临时豁免，必须由有权来源明确给出方向、时段及所覆盖政策版本，再按该豁免核对。完整日志证明无适用豁免时，完整逆向通行可得到 `unauthorized` 并带 `wrong_direction` 原因；政策、来源权限或豁免相互冲突时为 `uncertain`。不能只因存在一条授权消息就给禁止方向通行判 `authorized`。

授权必须包含可核对的有效范围与额度语义。一条“允许一辆车”的授权只能消费一次；一条授权允许多辆或车队时，额度须由协议显式给出。物理抬杆次数、车辆数量和授权数量是不同概念。

消费点由现场协议显式配置，例如进入边界、完整通行或控制器消费确认。完整授权键为 `controllerId + controllerEpoch + grantId`，额度单位另有 slot；同一 slot 只允许一次有效消费，`完整授权键 + slot + passageId` 对重复操作幂等。其他跨线和事件 UPDATE 不重复扣减，不能只凭 `grantId + passageId` 唯一就允许同一单次额度被两次通行消费。外部控制器作为额度权威时，本模块只读并核对消费结果，不向控制器修改额度。预约和已消费必须区分：`aborted` 只能按现场释放协议释放未消费预约，不能凭倒车录像返还已消费额度；消费点在完整通行时，越过进入线后但未完成就退回也可能仍属未消费预约。

视觉越线时刻是相邻可信帧之间的时间区间。该区间跨越授权生效、失效、撤销或时钟误差边界，且协议无法唯一判定适用性时，结果保持 `uncertain`；不能通过任意取前一帧或后一帧制造确定结论。

完整性判断至少需要来源持续性/序列、延迟水位与时钟质量。仅等待固定秒数而没有日志完整性证据，不足以将“没收到授权”变为 `unauthorized`。旧拒绝后出现新的有效授权、撤销消息与授权乱序、多个权威来源冲突，都依源协议重排核对；无法确定最终状态时保留冲突。

## 5. 闸杆状态、尾随与对象绑定

闸杆状态记录为开、闭、运动中或未知，注明其来源、观测时间和是否过期。视觉闸杆估计与控制器反馈冲突时保留双方依据并标记冲突。开闸不证明已授权；闭闸估计也不能独立证明车辆撞杆或非法通行。车辆授权有效但闸杆仍闭，可记录设备/信号异常，不能因此把授权改为无效。

尾随是车辆闯闸的一个判定原因，要求至少两次可靠区分的同车道、同方向通行，与同一放行过程具有足够关联，且尾车完整穿越后被判定为 `unauthorized`。前车已消费单次额度而尾车不存在独立有效授权，是典型证据。短车距或短时间间隔只能辅助关联。

若只能证明“两次通行合计超过一份额度”，却无法无歧义确定这份授权属于哪一次，则只记录通道容量差额与候选 passage 集合，两车个人 outcome 均保持 `uncertain`；不能默认第二个 tracker ID 就是尾随者。只有授权对象绑定或经现场协议固定的分配规则可靠成立，才指定某次通行为 `unauthorized`。

- 两车距离很近但各自授权有效：正常连续通行。
- 两车间距较大，第二辆借尚未关闭的闸口通过且无授权：仍可能尾随；不能仅因超出固定短间隔就排除。
- 同一拖挂车被拆成两条轨迹、两辆并排、车辆跨道插入：先解决目标计数/车道关联，不能先扣两份额度。
- 无法关联到同一放行过程但已确认无授权完整通行：可判一般未授权通行，不强行附加尾随原因。

身份绑定优先使用控制器提供的稳定、不透明授权关联信息，并结合车道、方向和有效时间核验。初版不新增车牌识别或人脸识别；若控制器已有对象引用也不能据此推断驾驶员身份。未来扩展车牌识别时，车牌文本仍只是一次观测；低置信、重复号牌、看不清、多个候选同时出现时不可唯一绑定。“最近的一次授权”“最近的车辆”“车辆前方有人刷卡”都不足以单独完成绑定。

## 6. 事件生命周期与契约限制

拟定事件类型为 `vehicle_gate_violation`。同一 `passageId` 的未授权、尾随等原因合并到一份 `PassageAssessment`，不为同次通行重复创建事件。`authorized`、`not_required` 和 `uncertain` 均保留通行审计；`uncertain` 可以在复核界面显示待核实，但不伪装成确定闯闸。

- **START**：完整通行已经确认且 outcome 收敛为 `unauthorized`。`startedAt` 对应所记录的完整穿越确认时刻，`observedAt` 为本版评估时间；授权晚到造成的决策等待不能伪装成实时发现。
- **UPDATE**：事件尚未结束时，补充证据或修订判定，沿用同一事件 ID，revision 单调增加。判定原因与 outcome 保存在对应的 `PassageAssessment`，不将其塞入 v1 固定字段。
- **END**：当前通行评估已收口，或源周期结束/中断使分析不能继续。结束原因在审计中区分正常完成、回退、失联、配置变化等。END 不表示车辆已安全清空闸区，也不表示平台已经处置告警。
- **即时收口**：授权水位到达时该通行已经完成且无需继续补证，可在同一批次依次输出 START、END，revision 分别增加，不人为延长事件。
- **幂等**：稳定事件 ID 关联 `passageId`；`idempotencyKey` 使用事件 ID 与 revision。同一通行的重试、重放和重复外部信号不新建通行、不重复扣减额度、不增加重复事件。

现有 `EventRecord` v1 只有固定字段，虽支持 START/UPDATE/END，但没有 `details`、`passageId`、outcome、授权信息或结束原因。本规范中的 `GateSignal`、`PassageAssessment` 和通行关联表属于待实现的版本化本地审计契约，不是对现有 `EventRecord` 的隐式扩展。不得把原因编码进 `status`、`modelVersion` 或 `confidence`，也不得声称未知字段会被现有平台保留。

超出约定迟到窗口后才出现反证时，以追加的 `PassageAssessment` 修订保留原判定、反证及关联事件 ID，转交复核。v1 无撤回语义，不能伪造 REVOKE、重开已关闭事件或偷偷修改历史消息；正式平台接入必须先约定可展示和处理该更正的流程，否则仅完成本地演示，不可宣称告警闭环验收完成。

## 7. 遮挡、重启与证据

短遮挡可暂存通行状态，但缺失观测既不证明持续行进，也不证明已离开；尚未完成通行就超过最大间隔时进入 `unknown`。遮挡前后的位置信息不足以证明连续完整穿越时，不能直线插值补造路径。同一源周期内只有唯一、可信的轨迹重关联才能延用 `passageId`，且须保留关联依据；单凭时间或位置接近不能合并。

重连、跳播或重启开始新的 source epoch，轨迹不跨周期延续；旧周期尚未完成的视觉通行须收口为 `unknown`，已完成通行的授权等待按下述规则保留。新周期首次已在闸口中的车只能产生不完整通行。授权去重与额度消费账本需要独立持久化，不随视频重启清空；账本无法恢复时额度结论降级为 `uncertain`，不重新消费一条可能已消费的授权。

视觉源结束和授权评估结束是不同边界。已经完整穿越但授权仍 `pending` 的 passage 保留 `completed` 与原 source epoch，在持久化的有限等待窗口继续接收控制器消息和 tick；EOF 或视频进入新周期不能抹掉完成证据，也不能把该候选提前当作 END 后更正。窗口到期后缺少完整性覆盖才收敛为 `uncertain`；授权评估已经收口后到达的反证才走追加评估修订。恢复这种待判记录不意味着恢复旧轨迹。

每个通行回放包保存源视频标识与哈希、固定检测/轨迹观测、GateSignal 输入、通行审计、EventRecord、场景/策略/模型版本、时间质量和期望结果。证据覆盖接近、越线、完成/退回及授权收敛过程；截图或片段缺失单独记录，不伪装为证据齐全。保留证据与授权映射时仅使用复核所需标识，不据此推断驾驶员身份。

## 8. 验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| 一授权、一车正常驶入 | `authorized`，一次 passage、一次消费，无闯闸事件 |
| 独立定义为自由驶出的方向 | `not_required`；仍记录通行，不借用入场授权 |
| 两车近距离，各自授权有效 | 两个正常 passage，不因短间距判尾随 |
| 一份单车额度、两车依次完整通过，日志完整且分配关系唯一 | 第一车正常；第二车 `unauthorized`，一条事件，保留尾随依据 |
| 通道容量不足，但授权归属或分配规则不唯一 | 保存通道差额及候选集合，个体 `uncertain`，不指定尾随者 |
| 禁止方向完整穿越，存在不适用该方向的普通授权 | 完整日志与可信政策证明无豁免时 `unauthorized`；方向豁免有效则按豁免核对，政策冲突则 `uncertain` |
| 第二车无授权但放行过程关联不足 | 一般未授权通行，不擅自认定尾随 |
| 探入、压线抖动、完成前退回 | 不确认完整闯闸；只释放未消费预约 |
| 消费后退回，再次越同一条线 | 不自动退款或重复扣减，不产生重复事件 |
| 授权在允许迟到窗口内到达 | 先待判，再按有效授权收敛，不抢先生成确定闯闸 |
| 日志断流、时间超差、绑定冲突、过期闸杆信号 | `uncertain` 或独立状态冲突审计，不推断无授权 |
| 完整通行，完整日志证明无适用有效授权，可伴有已关联拒绝 | `unauthorized`；同一 ID 的 START/END 正确收口，单条拒绝不绕过其他授权核对 |
| 已完整穿越但 pending，随后 EOF/重启，授权在等待窗口内到达 | 保留原 completed 证据，继续核对并正常收敛；不恢复轨迹、不复活额度 |
| 事件收口后出现授权反证 | 追加评估修订，保留历史并进入更正/复核流程 |
| 卡车/拖挂拆轨、骑手重复框、人员穿越车道 | 不按框数扣额度；不可靠计数时保持 `uncertain` |
| 遮挡跨越整个闸口、重启后已位于内侧 | 不补造完整穿越，不跨源周期拼轨 |
| 重复消息、乱序授权、Outbox 重试、重放 | 不重复扣额度，同一 revision 投递幂等 |
| 同次通行同时满足多个异常原因 | 一个事件，审计中保留多个有依据的原因 |
| 其他车辆在前一事件结束后紧接进入 | 独立 passage；不会被车道冷却吞掉 |

规则验收使用固定观测与模拟信号覆盖所有分支；真实视频验收另行评价检测、跟踪、目标计数、几何标定和授权绑定。至少报告事件精确率/召回率、每千次正常通行误报数、重复事件率、额度错误数、授权绑定正确率及覆盖率、`uncertain` 比例、延迟分位数，并按机位、昼夜、天气、车种、遮挡分组。统计指标与通过门槛在正式样本集冻结时确定，当前不承诺准确率、时延、低照度能力或现场可用性。

## 9. 完成时必须交付的可播放演示视频

车辆模块完成时必须交付实际可播放的视频文件，不能只交代码、JSON、截图或文字说明。最低交付为 `demo.mp4`、对应回放输入/配置、事件与通行审计、`run.json` 及观看说明。视频必须实际解码检查开头、中段、结尾和各关键事件片段；文件存在或编码器返回成功不等于验收通过。

| 演示章节 | 画面中必须看见的行为与结果 |
| --- | --- |
| 正常授权 | 车辆接近并完整驶入，适用授权与额度消费，最终 `authorized`，无闯闸事件 |
| 无授权 | 车辆完整穿越，显示授权流完整性/水位依据，最终 `unauthorized` 及 START/END |
| 尾随 | 两辆可区分车辆共享一份单车额度，分配依据明确支持第一车获准、第二车独立 passage 被判异常；另附两车各有授权的近距离负例 |
| 迟到授权与未知 | 授权迟到时先显示待判、到达后收敛；日志中断/绑定歧义时保持 `uncertain`，不能用字幕把它改成确定闯闸 |
| 事件结束 | 已生成事件正常收口或观测中断后的 ID/revision、END 与结束原因；退回但未生成事件时只展示 passage 结束，不伪造 END；区分收口和整车清空 |

视频同屏叠加原始画面、实际推理检测/轨迹、标定区域与方向、`passageId`、通行状态、outcome、闸杆状态及来源、授权/额度时间线、事件 phase/ID/revision 和时钟/数据质量。授权ID与车辆标识可采用演示专用标识，必须能与回放记录对应。

当录像经过真实模型推理而授权、闸杆或控制器信号来自模拟输入时，画面全程明确同时标注“视频检测/跟踪：真实模型推理”和“授权/闸杆信号：模拟输入”，逐项标明信号来源。若检测框或轨迹也是固定数据注入，必须明确改为“检测/轨迹：固定观测回放”，不得称为真实推理。实际接入的信号与模拟信号混用时，分别标注，不能统一写成“已联调”。

模拟信号可用于可复现地演示策略，但不能证明真实控制器兼容性、时钟同步、授权绑定或现场准确率。模块完成至少需要真实视频经过实际模型推理的可播放演示；仅有固定观测动画不足以满足此交付要求。缺少任何必需章节、无法播放、没有来源标注或未展示事件收口时，应明确标记演示未完成。

## 10. 落地顺序与当前状态

1. 冻结场景标定、类别计数、授权/额度协议、消费点与时间质量规则。
