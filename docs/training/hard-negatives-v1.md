### 固定窗口已暴露的新问题

本轮现有冻结姿态头在 ADL-10 真实缓存上的 1 秒固定窗口回放产生了 **1 次 START 误报**；使用的触发条件为 `start_score=0.75`、`confirm_seconds=1.0`。记录位于 `runtime/checks/fall-stream-20260923/adl-10/run.json` 和 `events.jsonl`：300 帧、82 次观测、14 次 unknown，START 后在片尾以 `source_end` 关闭。该 END 只是数据源结束，不能解释为人员已恢复。

旧模型使用增长前缀和整段描述符训练；固定窗口改变了输入分布。旧增长前缀在这段素材上没有阳性时点，不代表新固定窗口没有误报。新回放只证明该开发片段存在误报，不能从不足十秒素材外推可靠的每小时误报率。下一轮应使用相同窗口长度、采样点、步长、跟踪中断规则与 unknown 规则构建 train/val 描述符，先完成固定窗口模型与验证，再冻结用于独立 test。不能仅提高阈值来让这一个开发片段通过。

同轮复核还发现旧缓存允许多人检测结果中的一条轨迹有效，而新视频入口限定单人。统一规则、在多人/关联失效后重建轨迹后，最终 ADL-10 为 0 次告警、94 次观测中 41 次预热或 unknown。更低告警数量伴随更低可判断覆盖率，不是模型精度提高；前述未经单人规则统一的失败记录仍保留。完整对比见 [连续告警记录](fall-streaming-2026-09-23.md)。

## 采集与标注

优先采集正常行走、蹲下取物、弯腰、坐下/起立、嬉闹、主动躺卧；同时保留安全安排的跌倒与打架表演正例，用于检查降低误报时是否增加漏报。采集要覆盖不同人物、镜头俯角、距离、遮挡和光照。每条连续录像保留动作前、动作中与动作后的自然过程；跌倒重点保留“正常→跌倒→恢复”，不能把没有拍到恢复的片尾填成恢复。

只登记已有明确来源与适用授权的素材，原视频保存在忽略目录 `datasets/private/` 或受控存储，不提交真人视频。用稳定匿名 ID 记录所有可见人物，实际身份映射另行受控保存。标注文件可附 `provenance` 字段记录来源、授权/同意记录引用、采集日期、标注者、复核者和原录像指纹；CSV 审计不代替人工核验这些记录。

事件真值应人工复核：跌倒开始是失衡/不可控下落的开始，结束边界按预先冻结的任务定义记录，另外记录恢复时点；持续躺地不等于持续跌倒运动，主动躺卧不能标成跌倒。无法判断或被遮挡的片段应标明原因，不能按模型分数补造真值。其他动作也要保留起止时间，分类主标签不代替时间标注。

`annotation_path` 指向对应录像的 JSON。与连续事件评估器共用的基础结构是 `sessions` 和 `events` 两个数组：每项包含 `cameraId`、非负整数 `sourceEpoch`、带时区 ISO `startedAt`、`endedAt`，事件可另含 `eventId`；`events: []` 表示经复核无目标事件。`sessions` 必须覆盖已复核的实际观测区间、非空且同源不重叠；事件必须完整落在一个 session 内且同源不重叠。相对视频秒数需按记录的基准时间转换，不能使用处理耗时。其他动作和恢复可放扩展字段，目标事件 `events` 只放本次评估的事件类别。审计器严格模式仅核验标注文件存在，JSON 语义由事件评估器和人工复核检查。

## CSV 合同与划分

模板 [continuous-sessions.csv](../../datasets/templates/continuous-sessions.csv) 只有表头，没有编造样本。每行代表一个实际视频文件；多动作录像使用主行为标签，时间标注中保留全部动作。

| 列 | 规则 |
| --- | --- |
| `clip_id` | 唯一片段 ID；禁止重复 |
| `path` | 实际视频文件路径；相对路径从 `--project-root` 解析 |
| `split` | 显式填 `train`、`val` 或 `test`；工具不自动重分 |
| `person_ids` | 所有可见人物稳定匿名 ID，以分号分隔；不按录像重编号 |
| `camera_id` | 稳定物理摄像头 ID；不按录像/日期重编号 |
| `source_group` | 独立原录像/同一表演 ID；同一录像的片段、裁剪、重编码及同步双机位共用 |
| `behavior` | 仅使用下表英文标签 |
| `duration_seconds` | 实际片段的正数时长；不能填帧数 |
| `annotation_path` | 对应已复核 JSON 路径，正常录像同样需要 |
| `sha256` | 当前视频文件完整字节的 SHA-256，64 位十六进制 |

| 标签 | 行为 |
| --- | --- |
| `normal` | 正常活动 |
| `squatting` | 蹲下 |
| `bending` | 弯腰 |
| `sitting_down` | 坐下 |
| `play_fighting` | 嬉闹/假打 |
| `lying_down_voluntarily` | 主动躺卧 |
| `fall` | 跌倒 |
| `fight` | 打架 |

先按人物、物理摄像头及原始录像的关联组冻结 split，再切片/增广；任何相同人物、摄像头、`source_group`、文件路径或 SHA 都不得跨 split。若同一人出现在两台摄像头，两者所在关联组应一并分配，不能靠更换 ID 获得表面隔离。ID 比较忽略大小写和首尾空格。缺失或 `unknown` 的人物/相机只可作为待补登记的开发记录，不能通过严格准入或支撑跨人物/摄像头结论。

严格审计会读取文件实际 SHA，即使表中填不同 SHA 也无法隐藏跨集相同文件。SHA 只能识别字节相同的副本；裁剪/重编码/相邻片段仍依赖人工来源登记和 `source_group`，不能靠 SHA 代替来源审查。报告的独立组数按 `source_group` 去重，类别中同组可重复出现；不能把各类别组数相加作为新录像数。时长只是已列片段时长，可能重叠，不可充当每小时误报的曝光分母。

## 执行审计

在项目根目录运行，实际清单放在忽略目录，例如 `datasets/private/continuous-v1/sessions.csv`：

```bash
# 初步登记检查；不读取视频字节，输出明确标为 metadata_only。
.venv/bin/python -m campus_safety_ai.apps.audit_continuous_manifest \
  --manifest datasets/private/continuous-v1/sessions.csv \
  --project-root . \
  --output runtime/audits/continuous-v1-draft.json

# 正式准入：三个 split、所有身份/哈希/标注完整，且文件存在、SHA相符。
.venv/bin/python -m campus_safety_ai.apps.audit_continuous_manifest \
  --manifest datasets/private/continuous-v1/sessions.csv \
  --project-root . --strict \
  --output runtime/audits/continuous-v1-strict.json
```

报告文件拒绝覆盖；使用新的输出文件名保存每轮审计。退出码 0 表示该模式检查通过，1 表示审计失败，2 表示命令行/输出目标问题。空模板会失败并列出缺少数据，不会被当作已完成采集。默认模式通过只表示元数据未发现已知冲突；严格模式通过也不证明标签质量、人数代表性或模型效果。按 train/val/test 分别报告片段数、原始组数及八类行为的缺口；缺少类别作为警告，不能把“审计通过”当作“素材已足够”。

## 下一轮训练与验收边界

1. 原模型和旧清单保留；新增数据按冻结人物/摄像头/原录像组完成来源及标签复核。各 split 补齐困难负例及正例，报告独立组数和实际复核时长。
2. 固定窗口训练仅用 train，标准化只由 train 拟合。val 选择窗口、模型、触发/结束/冷却阈值；分别检查困难负例误报及正例漏报。unknown、遮挡与跟踪重置不能当负例补零。
3. 冻结清单、标签、checkpoint、推理及事件配置 SHA 后才运行独立 test；不反复根据 test 调参。已经用于诊断的数据退回开发证据，不冒充新的留出集。
4. 用连续事件真值统计每小时误报、事件漏报及 unknown 覆盖。分母来自实际复核会话和可观测时间；短片拼接/重复回放/重叠窗口都不增加独立时长。报告观察时长与事件数量，不仅给百分比。
5. 工程回放、困难负例集和目标设备长稳测试分别记录；本轮没有 RK3588 或真实平台验证结果。只有新独立验证支持时，才能宣称识别能力提高。
