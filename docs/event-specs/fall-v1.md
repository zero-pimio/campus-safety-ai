# 跌倒动作事件 v1（实验）

事件类型为 `person_falling`，行为观测为 `falling`。现有模型只识别跌倒转变，不判断人员安全，也不独立检测静止躺地。适用范围是保守的单人轨迹；多人、姿态不足、关联失败为 unknown。

## 时间窗口与状态

- 固定 1 秒历史窗口，默认每至少 0.1 秒推理一次（落在下一个实际帧上）。窗口内 16 个等分时间中心各取不晚于该中心的真实帧；不重复帧凑数，不读取未来。
- 最多保存 256 个姿态帧，实时视频不累计全量结果。未覆盖完整窗口、实际帧不足、相邻帧间隔超过 0.3 秒或轨迹重建时输出 unknown 并重建历史。
- 默认分数连续至少 0.3 秒不低于 0.5，发 START。确认从第一条阳性观测的 `observedAt` 开始，不把整个窗口时长算作已经确认。
- 开放事件默认连续至少 1 秒不高于 0.35，发 END，原因 `motion_cleared`。分数处于迟滞区间或 unknown 会中断确认/清除计时。结束后冷却 2 秒。
- unknown 不按零分处理；它不能证明动作结束或人员恢复。确认中的 unknown 重置候选，开放事件可在 unknown 期间保持，直至真实清除或明确源/轨迹边界。
- 明确轨迹更换、超过事件最大观测间隔、新源周期、EOF、解码失败或主动中断会关闭开放事件并记录原因。边界结束不代表人员恢复。
- 同一源周期的重复/过时观测不重复触发；事件 ID 稳定、revision 单调、幂等键为 `eventId:revision`。结束后再次运行同摄像头需增加 `sourceEpoch`。

这些默认值是本轮预先确定的工程参数，未通过人工事件真值调优。尤其旧分类头没有按此固定窗口训练，不能由默认配置推导校园告警效果。

## 数据与交付

`FallObservation.score=null` 表示 unknown，`reason` 解释预热、人数或姿态等原因。它独立于原打架观测合同，不将 unknown 塞进合法概率。

本地 `observations.jsonl` 保存窗口、分数、质量及采样序号；`events.jsonl` 在已有 EventRecord 上增加 `sourceEpoch` 与 `reason`，供审计和事件评估。平台收到的 EventRecord 保持原 schema。START 抓拍成功后 END 继承同一证据 URI；截图失败单独计入运行报告，不阻断事件。

事件先写 SQLite Outbox，再投递。默认只写本地 JSONL；显式 `--platform-config` 可接已有平台 adapter，EasyAIoT 使用后台交付。按原有 at-least-once 交付语义，接收端仍需幂等，不能保证外部通知恰好一次。

默认本地文件时间为 CFR 帧号/FPS，缓存回放使用已有官方时刻；RTSP 使用接收时的单调时间锚定 UTC，不声称是原始采集时刻。RTSP 连接/读取超时设置为 5 秒，读取结束关闭当前事件；自动重连尚未实现，实际超时行为也需目标 OpenCV/摄像头验证。

## 评估定义

真值 JSON 的 `sessions` 给出完整、已标注的摄像头/源周期观测时段，`events` 给出该时段内目标事件起止；正常会话使用空 `events`。同摄像头/周期的会话和事件不得重叠。源文件均使用带时区时间，不以程序运行耗时替代视频时长。

评估只按唯一 START 的实际 `observedAt` 匹配真值，默认容差 0 秒，一次告警最多命中一个事件。迟于标注结束的告警默认计误报，对应真值计漏报；若需要容差，应在独立测试前冻结，不能事后为通过而扩大。

- 每小时误报 = 未匹配告警 / 全部已标注摄像头会话小时，同时报告正常时长。
- 事件漏报率 = 未匹配真值 / 真值总数；没有真实正事件时为 null，不写成 0。
- 延迟 = START 的 `observedAt` − 真值开始，不使用回溯的 `startedAt` 美化延迟。
- 已知/unknown 覆盖按相邻观测间的时间累计；超过允许间隔及首尾无观测区间单列 unobserved。unknown 包含预热，不从分母删除。

`unknown_fraction` 是时间占比，不能用 unknown 观测条数占比冒充。误报率必须和时长、独立录像数、漏报率及覆盖率一起阅读。短开发录像的零告警不能外推长期零误报。
