# 阶段门禁

本文件是门禁速查表；完整范围、架构、16 周安排、验收指标、风险和当前状态见 [PROJECT-PLAN.md](PROJECT-PLAN.md)。领域术语以根目录 [CONTEXT.md](../CONTEXT.md) 为准。

2026-09-23 增补：车辆闯道闸与人员闯门禁共同纳入 [联动设计](design/access-control-v1.md)，当前为待实现阶段；现有 fall 等模块的最新结果以 [推进记录](training/project-progress-2026-09-23.md) 为准。**所有模块阶段完成时都必须交付并展示可播放演示视频**，各模块缺项与验收见 [视频交付清单](demos/DELIVERY.md)。以下 G0–G7 为原阶段顺序，不代替最新模块状态。

- G0：项目内部冻结事件范围、板卡型号、摄像头规格、模型约束、隐私和验收指标。
- G1：固定行为观测/检测结果 → 事件 → SQLite Outbox → JSONL/假平台。本仓库已完成本地链路、配置装配和断流/丢轨收口；OpenRemote 假事件尚未完成。
- G2：目标板卡官方样例、模型第一帧、100 图输出比较、30 分钟视频稳定性。
- G3：PC 端 PP-TSM/PyTorch/ONNX 分类、时序状态机、本地截图/采样短片和 Outbox 已完成；真实 RTSP、证据保留策略和远程发布闭环待完成。
- G4：按摄像头/日期划分校园数据，报告检测和事件指标。
- G5：板卡端完整视频闭环、断流/断网和 8 小时稳定性。
- G6：依次增加非法闯入和车辆违停。
- G7：基线稳定后再做 INT8、蒸馏、剪枝、跌倒/超速、追逐和 Mage-VL 复核。

门禁失败时不自动进入下一阶段。每次模型、量化、板卡或规则变化都重跑固定 Detections JSONL 和完整视频 ReplayBundle。
