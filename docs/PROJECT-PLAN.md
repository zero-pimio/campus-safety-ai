# 校园安全边缘 AI 总项目规划

版本：v1.0 草案  
规划日期：2026-08-25  
适用范围：固定校园摄像头、首期单路视频、一款边缘设备、OpenRemote 告警闭环。

## 1. 项目结论

本项目不是“训练一个万能 YOLO 模型”，而是构建一条可验证、可替换、可回放的视频事件链：

```text
视频源
  → Perception.detect(FramePacket) → Detections
  → EventAnalysis.advance(Detections) → EventRecords
  → EventDelivery.submit(EventRecords) → DeliveryResult
  → OpenRemote 告警与人工处置
```

当前交付顺序调整为：

```text
人员打架 + 非法闯入 + 车辆违停
+ 一款边缘设备 + OpenRemote 告警闭环
```

人员打架是第一条实现主线。跌倒、超速、骑车看手机、追逐、跨摄像头 ReID、Mage-VL 复核和多芯片同时适配均为扩展项，不得挤占主线。

## 2. 成功标准

项目完成不是“演示视频上出现了框”，而是同时满足：

1. 固定录像能重复产生一致的事件生命周期和证据；
2. PC 与目标板卡使用同一事件策略和事件契约；
3. 平台断网不阻塞视频处理，恢复后不丢事件、不重复创建平台事件；
4. 模型、数据、策略、场景标定和运行环境均可追溯；
5. 检测指标、事件指标、误报、端到端性能和稳定性都有报告；
6. 团队可以替换模型或板卡运行时，而不重写事件和平台逻辑。

以下是 G0/G2 前的建议工程目标，不是已经达到的结果；项目范围和板卡基线完成后再冻结：

| 维度 | 建议首期目标 |
|---|---|
| 非法闯入事件 | 锁定测试集 Recall ≥ 95%，Precision ≥ 90% |
| 误报 | 目标机位困难负样本回放无已知系统性误报；长视频目标 ≤ 1 次/摄像头小时 |
| 事件延迟 | 规则持续时间满足后，写入 Outbox 的 P95 ≤ 500ms；局域网投递 P95 ≤ 1s |
| 单路性能 | 目标板 1080p 单路处理 ≥ 10 FPS，队列不无限积压 |
| 转换损失 | 板卡事件 Recall 相对 PC 基线下降不超过 2 个百分点 |
| 稳定性 | 连续 8 小时无进程崩溃；模拟平台离线 10 分钟后事件完整补传 |

## 3. 范围与优先级

| 优先级 | 内容 | 本期承诺 |
|---|---|---|
| P0 | 单路视频、打架视频分类、时序状态机、证据、可靠投递 | 必做 |
| P1 | 非法闯入、校园数据基线、目标板完整视频闭环 | 必做 |
| P2 | 车辆违停、OpenRemote 看板、8 小时稳定性 | 必做 |
| P3 | 跌倒或超速、多路视频、INT8 优化 | 条件允许 |
| P4 | 看手机、追逐、Mage-VL、跨镜跟踪 | 研究扩展 |

后续扩展事件选择规则：

- 有固定道路机位、四点地面标定和可信速度真值时选“超速”；
- 没有速度真值，但能安全采集跌倒与易混淆负样本时选“跌倒”；
- 两项条件都不具备时，不承诺该扩展事件，先补齐数据条件。

## 4. 领域语言

全体成员以根目录 [CONTEXT.md](../CONTEXT.md) 为准：

- 检测是单帧模型观测，不是事件；
- 轨迹是一个视频源周期内的临时目标，不是人员身份；
- 候选事件不能直接发布；
- 事件记录是边缘端事实，告警是 OpenRemote 的展示或通知；
- 回放包用于验证，流水线包用于部署。

文档、代码、报告和答辩中禁止把这些词混用。

## 5. 架构与深 module

### 5.1 Perception

```text
detect(framePacket) -> Detections
```

它隐藏视频帧预处理、模型运行时、输出解码、坐标还原、类别映射和精度差异。PC 上可使用 Ultralytics/Paddle，板卡上可使用 RKNN 或 Ascend；调用方只看项目原生 `Detections`。

外部 interface 必须包含：输入图像语义、原图坐标、空检测与推理失败的区别、模型版本、最大可接受延迟和启动兼容性检查。

### 5.2 EventAnalysis

```text
advance(detections) -> list[EventRecord]
```

它内部承载跟踪、区域判定、候选事件、去抖、START/UPDATE/END 生命周期和事件策略。Supervision ByteTrack 是内部实现，不提升为外部 seam；只有出现第二个真实跟踪实现时再抽取内部 interface。

它是纯进程内依赖，测试只通过 `advance()` 输入固定检测结果并观察事件记录，不绑定 ByteTrack 内部状态。

### 5.3 EventDelivery

```text
submit(eventRecords) -> DeliveryResult
```

它隐藏证据保存、SQLite Outbox、重试、退避、幂等确认以及 OpenRemote/MQTT 字段映射。SQLite 和本地文件属于可本地替换依赖；OpenRemote 属于真实外部依赖，生产 adapter 与内存 adapter 位于其内部 seam。

正式实现必须让写入 Outbox 与远程投递解耦：`submit()` 只负责持久化并快速返回，后台 worker 负责远程投递。当前同步 `flush()` 仅为 G1 演示，不满足正式 interface。

### 5.4 应用装配

`offline_replay` 和 `edge_agent` 只负责读取配置、创建三个 module、驱动主循环和生命周期管理。业务规则不得散落在 CLI、摄像头 adapter 或平台 adapter 中。

## 6. 依赖与开源项目角色

| 项目 | 角色 | 采用方式 | 不允许 |
|---|---|---|---|
| Ultralytics | PC 检测基线 | `Perception` adapter | 事件逻辑直接读取其 Results |
| Supervision | ByteTrack、区域和几何工具 | `EventAnalysis` 内部实现 | 用按 FPS 计时替代真实时间戳 |
| PaddleDetection | 跌倒、违停、闯入算法对照 | 独立实验与结果 adapter | 整套 pipeline 成为第二个事实源 |
| Frigate | 可选 NVR、录像与 RTSP sidecar | 仅在 G0 明确需要回看时接入 | 同时发布重复告警或替代稳定契约 |
| RKNN Model Zoo | Rockchip 转换/推理样例 | G2 板卡验证 | 当作完整业务应用 |
| Ascend samples | 昇腾 ACL/CANN 样例 | G2 板卡验证 | 同时维护第二条完整芯片主线 |
| OpenRemote | 设备、告警、看板和处置 | `EventDelivery` 目标 adapter | 承担视频推理或事件真值计算 |

许可证在冻结依赖时逐项登记。Ultralytics/OpenRemote 的 AGPL 边界、Paddle/Supervision/RKNN 的代码许可，以及每个模型和数据集的单独条款都必须写入 manifest。

## 7. 数据与评测体系

### 7.1 数据分层

1. 通用公开数据：仅用于预训练/基线，记录原始来源和许可证；
2. 校园开发数据：用于调参和错误分析；
3. 校园锁定测试集：按摄像头或日期隔离，禁止反复调参；
4. Golden 回放：少量确定性场景，验证状态机和完整链路；
5. INT8 校准集：来自真实机位，但与测试集分开。

隐私视频不提交 Git。仓库只保存 manifest、哈希、标注版本、授权范围和受控存储位置。

### 7.2 每个事件的数据必须包含

- 正样本：不同距离、人数、遮挡、光照和持续时间；
- 困难负样本：与事件相似但不应报警的行为；
- 边界样本：刚好触碰区域、短暂进入、轨迹中断和时间阈值附近；
- 故障样本：丢帧、乱序、断流、时间跳变和低置信度误检。

### 7.3 评测分两层

- 感知层：Precision、Recall、mAP、框 IoU、关键点指标；
- 事件层：事件 Precision/Recall/F1、开始/结束时间偏差、每小时误报、重复事件和漏结束事件。

不能用高 mAP 代替事件正确，也不能用一段演示视频代替锁定测试集。

## 8. 事件实施顺序

### 8.1 非法闯入

```text
person 检测 → 跟踪 → 底部中心进入禁区
→ 持续 T_enter → START
→ 离开持续 T_exit / 策略定义的轨迹终止 → END
```

G3 前必须补齐：轨迹消失如何结束、摄像头重连如何收口、边界点算内还是外、ID 切换如何避免重复告警、证据失败如何标记。

### 8.2 车辆违停

```text
车辆检测 → 跟踪 → 底部中心位于禁停区
→ 世界/像素位移低于阈值 → 持续停车时间
→ 排除红灯、拥堵、临时上下客等场景 → 事件
```

违停不能简化为“单帧车辆在区域内”。先使用 Paddle PP-Vehicle 作为对照，再把最终策略落入本项目 EventAnalysis。

### 8.3 跌倒或超速

- 跌倒：Pose/关键点 + 髋部下降 + 躯干方向 + 地面状态持续；必须包含坐下、蹲下、弯腰、系鞋带和躺卧负样本。
- 超速：地面标定 + 世界坐标轨迹 + 真实时间差 + 平滑；没有速度真值时只能称“运动速度异常”。

## 12. 测试矩阵

| 层级 | 测试对象 | 关键场景 |
|---|---|---|
| 契约 | Detections/EventRecord/配置 | 缺字段、版本不匹配、空检测、结构化失败 |
| EventAnalysis | 固定 Detections 回放 | 边界、短暂进入、ID 切换、轨迹丢失、重连、冷却 |
| EventDelivery | Outbox 与目标 adapter | 重复提交、进程重启、网络失败、恢复、平台重复确认 |
| 完整视频 | ReplayBundle | 模型/规则/板卡变化后的事件一致性 |
| 输出一致性 | PC/ONNX/FP16/INT8/板卡 | 类别、置信度、框 IoU、事件 Recall 和延迟 |
| 故障 | 视频/平台/存储/时间 | 断流、丢帧、积压、磁盘满、时钟跳变 |
| 长稳 | 完整边缘链路 | 8/24 小时、内存增长、温度、功耗、队列深度 |

测试只跨三个主要 interface 观察结果。替换跟踪器或 SDK 后，如果业务行为不变，测试不应重写。

## 13. 风险与止损

| 风险 | 早期信号 | 止损动作 |
|---|---|---|
| 板卡转换失败 | G2 第一帧或算子不兼容 | 立即切回回退模型，不改事件契约 |
| 七类事件并行失控 | G3 前出现多个半成品分支 | 停止 P3/P4，只保留打架主线 |
| 校园域差异 | 公开数据好、目标机位误报高 | 收集困难负样本，按机位评测 |
| 轨迹 ID 切换重复告警 | 遮挡后产生新事件 | 候选合并、冷却、ReplayBundle 回归 |
| 平台断网拖慢推理 | 队列增长、视频延迟累积 | Outbox 异步 worker、丢过期帧、不丢事件 |
| 磁盘被证据占满 | 剩余空间持续下降 | 配额、保留策略、证据失败仍保留事件 |
| 许可证不清 | 权重或数据没有明确条款 | 隔离实验，未确认不得进入发布包 |
| “超速”无真值 | 只有像素位移 | 改称速度异常或取消该事件 |
